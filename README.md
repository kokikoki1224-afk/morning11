## STEP3で確定したUSD/JPYの正式基準

**yfinance `JPY=X` の日足は使用しない。** 1時間足からNY17:00（米東部時間）に最も近いバーを取得し、その始値をその日の代表値とする。前営業日の同じNY17:00スナップショットとの差分から前日比を計算する。この方式を「日本株モーニング11」のUSD/JPYの正式基準として採用する（実装: `data/market.py` の `_yfinance_hour_snapshot`（STEP5で日経225先物と共用できるよう汎用化）、設定: `config/settings.json` の `overseas.usdjpy.primary.provider = "yfinance_snapshot"` + `tz/hour/field`）。下記「USD/JPYの基準時刻問題」に記載の限界事項は解消されたわけではなく、引き続き有効な既知の限界として残す。

### 1. 日経225先物（NKD=F）の基準時刻検証

USD/JPYと同様、**単純な日足Closeは採用していない。** 時間足(`interval="1h"`)をJST変換して実データを検証した結果、次のことが分かった。

- CME（Nikkei/USD先物）には**JST06:00〜07:00頃に日次メンテナンス休止**があり、その前後で明確なバーの断絶がある（例：`...05:00`の次が`07:00`に飛ぶ）。
- 月曜日はこの休止がさらに長く、JST07:00（＝日曜17:00 CT、CME週間再開時刻）まで一切バーが無い。これは「日本株寄り付き前」が実質的に生成される時間帯（JST7:00前後）と、CMEの日次区切りがほぼ一致していることを意味する。
- yfinanceの**日足`Close`もこの検証と矛盾しない**（USD/JPYのような時系列上ありえない値は出なかった）。ただし日足の「Date」ラベルはニューヨーク時間の暦日で付与されており、実際の内容はJST翌朝5時台まで続くため、ラベルだけを見ると「どの朝の値か」を誤解しやすい。
- そこで**JST05:00台バー（休止直前の最終バー）のCloseを「その営業日の代表値」として明示的に切り出す方式**を採用した（USD/JPYと同じ`_yfinance_hour_snapshot`を`tz="Asia/Tokyo", hour=5, field="Close"`で再利用）。これにより「日足のCloseだから採用」ではなく、「休止直前＝大取夜間取引終了に相当する、朝の判断に意味のある値」であることを明示的に保証している。

**実測による裏付け**：2026-09-05のJST05:00台バーのCloseは**65,820**。これは前回セッションで手動確認した実際の大取夜間取引清算値（**約65,830**）とわずか10円（0.015%）差で、CME先物（ドル建て）とOSE先物（円建て）の建値差として十分説明できる範囲。日足`Close`ベースでも同じ65,820が得られており、今回の検証範囲では両者は一致した（ただし前述の通りラベルの意味が分かりにくいため、明示的なJST05:00スナップショット方式を正式採用とする）。

### 2. TOPIX連動ETF（1306.T）

STEP2で`^TOPX`・`^TPX`が取得不可（データなし）と確認済みのため、**TOPIX指数そのものではなく連動ETF「NEXT FUNDS TOPIX連動型上場投信」（1306.T）を代理指標として採用**。東証の単一立会時間（9:00-15:00 JST）内の通常の日足Close/Openで前日比を計算しており、USD/JPYや日経225先物のような基準時刻の曖昧さは無い。**HTML上でも指標名を「TOPIX連動ETF（1306.T）」と明記し、指数そのものと同一ではないことが常に分かるようにした**（`templates/morning11.html` の固定テキスト）。ETFの価格変動率は指数のそれとほぼ一致するが、分配金落ち・信託報酬・需給要因により完全一致はしない点に注意。

### 3. 日本10年国債利回り（財務省公式CSV）

候補どおり**財務省「国債金利情報」公式CSVを採用**（無料・公式・APIキー不要）。当月分の軽量CSV（`jgbcm.csv`、Shift-JIS/CP932エンコード）を第一候補とし、月初などで当月分が2行に満たない場合のみ全期間CSV（`jgbcm_all.csv`）にフォールバックする。日付は「R8.9.3」のような和暦（令和/平成/昭和）形式のため、`_era_to_iso_date()`で西暦ISO形式に変換している。10年債の列は基準日を含めて11列目（0始まりで10番目）。前日比は**％ではなくbpで扱う**（`change_bp`フィールド、他の利回り指標と同じ構造）。公式CSVは実際の取引日より1日程度遅れて公表される場合があり、今回の検証でも他の指標が9/4時点なのにMOFデータは9/3時点までだった（米10年債のFRED同様、公式データの公表ラグとして許容する）。

## スコア計算（STEP3）

対象は Nasdaq / SOX / 米10年債利回り / USD/JPY / KOSPI の5指標（実装: `analysis/score.py`）。データ取得（`data/market.py`）とスコア判定（`analysis/score.py`）は責務を分離しており、スコア計算はネットワークアクセスを一切行わない。

- ±0.2%ルール（Nasdaq/SOX/USD-JPY/KOSPI）：`change_percent >= +0.2` → `+1`、`<= -0.2` → `-1`、それ以外 → `0`
- 米10年債はbp閾値・符号反転：`change_bp <= -3` → `+1`（金利低下は好材料）、`>= +3` → `-1`、それ以外 → `0`
- 欠損指標（`status != "OK"`）は**推測値を入れず、スコアに加算しない**。`available`（取得できた指標数）と`total`（5）を必ず保持し、一部欠損時は`provisional=true`として「4/5指標取得・暫定スコア +3」のように表示する
- 総合判定：`+3〜+5`→追い風、`-2〜+2`→中立・やや方向感なし、`-5〜-3`→逆風

テスト（`tests/test_score.py` `tests/test_market.py` `tests/test_generator.py`、`python -m pytest` で49件全て合格確認済み）：
- ±0.2%ルールの境界値（+0.3/+0.2/+0.19/0/-0.19/-0.2/-0.3 → 1/1/0/0/0/-1/-1）
- 米10年債bp閾値の境界値（-4/-3/-2/0/+2/+3/+4bp → 1/1/0/0/0/-1/-1）
- 欠損指標が0点ではなく「加算されない」ことの確認、`available/total`の整合性
- USD/JPY・日経225先物が日足関数を呼ばず時間足スナップショット関数を呼んでいることのモック検証
- 財務省CSVのパース（和暦→西暦変換、10年債列の抽出、当月分不足時の全期間CSVへのフォールバック）
- 日本市場3指標の取得失敗が海外5指標のスコアに一切影響しないことの確認

既存のclaude.ai artifact・Claudeスケジュールタスク（`nihonkabu-morning11`）とは完全に独立しており、それらは変更していない。

### USD/JPYの基準時刻問題（調査結果と対応）

**問題**：yfinanceの`JPY=X`日足（`interval="1d"`）は、24時間ほぼ連続で取引されるFXペアの集計区間があいまいで、実際に時間足と突き合わせたところ、日によっては前日比の符号（円高/円安）が逆転するほどの不整合を確認した。

検証例（2026-09-02〜09-03、時間足ベースで正しい値動きを追った場合）：
- 日足`Close`の系列：9/1=159.747 → 9/2=**160.196**（前日比+0.28%＝円安） → 9/3=158.923
- 同じ期間を時間足(1h)で丁寧に追うと、9/2の実際の値動きは159台からザラ場で158円台へ**下落**しており、日足の「9/2=160.196」という値は時系列上ありえない（前後のどの時間足バーにも該当する値がない）。yfinanceの日足エンドポイントが、24時間連続取引銘柄で内部的に取り違えている可能性が高い。

**対応**：日足を使わず、時間足(`interval="1h"`)を取得し、日本の為替報道が慣行的に「その日の終値」として扱う**NY17:00（米東部時間）**に最も近いバーの始値を「その日の代表値」として採用し、前日の同時刻との差分でスコア判定する。これにより時系列上の整合性を確認済み（例：9/2のNY17時値=158.674、9/3のNY17時値=155.779〜155.848）。

**残る限界**：日本の為替速報記事（外為どっとコム等）が引用する「終値」は、記事執筆時点のアドホックな時刻を指すことが多く、NY17:00ちょうどとは数十分〜1時間程度ズレることがある。今回の検証でも0.3〜0.5円程度の差が残った。これは「NY17:00」という一貫した基準を採用したことによる説明可能な差であり、日足エンドポイントの不整合（符号が逆転しうる）とは性質が異なるため許容する。

**運用上の注意**：本番（GitHub Actionsで日本時間朝に実行）では前営業日のNY17:00は確実に経過済みのため問題ないが、当日の途中経過を見るような使い方をすると直近日のスナップショットが未確定になる場合がある。

日経225先物・TOPIX連動ETF・日本10年債の検証詳細は上記「STEP5: 日本市場3指標の追加」を参照。
